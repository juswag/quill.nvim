1. INTRODUCTION                                           *quill-introduction*

Select lines, describe a change, and quill streams the model's rewrite as a
preview drawn with extmarks over your code. The buffer is not modified while
you review. Accepted hunks are written in one change, so one |u| undoes them.

Requires Neovim 0.10 or newer and `curl` on $PATH. The `codex` and
`claude_code` providers need their CLI on $PATH instead.

2. SETUP                                                         *quill-setup*

                                                              *quill.setup()*
require("quill").setup({opts})
    Merges {opts} into the defaults and creates the mappings: visual mode
    starts an edit, normal mode opens the ask box.
    Defaults: >lua
    {
      provider = "openai",
      providers = {
        openai = { base_url = "https://api.openai.com/v1",
                   model = "gpt-4o-mini", api_key_env = "OPENAI_API_KEY" },
        anthropic = { base_url = "https://api.anthropic.com/v1",
                      model = "claude-sonnet-4-5",
                      api_key_env = "ANTHROPIC_API_KEY" },
        codex = {},
        claude_code = {},
        copilot = { model = "gpt-5-mini" },
        mock = {},
      },
      context_lines = 20,
      mapping = "<leader>k",
      keys = {
        accept = "a", reject = "r", accept_all = "A", reject_all = "R",
        next = "]h", prev = "[h", followup = "f",
        edit = { "<CR>", "e" }, expand = "<Tab>",
        cancel = { "q", "<Esc>" },
      },
    }
<
    `provider`       Name of the entry in `providers` to use.
    `context_lines`  Lines above and below the selection sent as context.
    `mapping`        Visual-mode edit and normal-mode ask mapping, or false.
    `keys`           Buffer-local keys active during an edit or ask session.

3. COMMANDS                                                   *quill-commands*

                                                                      *:Quill*
:[range]Quill [instruction]
    Start an edit on [range]. Without [instruction] a prompt opens.

    The prompt buffer has 'filetype' `quill_prompt`, and completion is turned
    off in it for blink.cmp, nvim-cmp, mini.completion, and built-in
    completion, so <CR> always submits. Match the filetype to exclude it from
    another completion plugin.

                                                                   *:QuillAsk*
:QuillAsk [question]
    Ask about the code under the cursor. Without [question] a small box
    opens at the cursor to type in. See |quill-ask|.

                                                                *:QuillCancel*
:QuillCancel
    Cancel the edit or ask session in the current buffer and stop its
    request.

==============================================================================
4. REVIEW KEYS                                                    *quill-keys*

While a session is open these normal-mode keys are mapped in the buffer:

  a        Accept the current hunk and move to the next pending one.
  r        Reject the current hunk and move to the next pending one.
  A        Accept every remaining hunk.
  R        Reject every remaining hunk.
  ]h  [h   Next or previous pending hunk.
  f        Open a follow-up prompt. The request includes the previous
           instruction and proposal. The range stays the same.
  q  <Esc> Cancel the session.

When no pending hunks remain, the accepted hunks are written and the session
closes. The mappings are removed when the session ends.

5. ASK                                                             *quill-ask*

In normal mode, |<leader>k| (or |:QuillAsk|) opens a small box at the cursor.
Type a question and press <CR>. The box shows a spinner until the answer is
ready, then morphs in place into the answer. Nothing is streamed into the
box, and the source buffer is not modified.

The request includes the enclosing function (or nearby lines when there is
no function), the file name, and the filetype, from the current file only.
It goes through the same provider abstraction as an edit. Identifiers wrapped
in backticks and "line N" mentions in the answer are highlighted in the box
and on the matching ranges in the buffer while the box is open.

The box is capped at 8 lines. These normal-mode keys are mapped in the
source buffer while it is open:

  e  <CR>  Close the box and start an edit of the enclosing function
           (or the nearby lines). The instruction is the question plus
           the answer, reviewed as hunks.
  <Tab>    Expand a truncated answer.
  q  <Esc> Close the box.

The box also closes when the cursor leaves that function (or those nearby
lines), or when leaving the window or entering insert mode in the file.
Asking again replaces the current box. `:QuillAsk why could this return
nil?` skips the prompt.

6. PROVIDERS                                                 *quill-providers*

`openai`       Chat Completions with `stream = true`. Works with any
               OpenAI-compatible server through `base_url`.
`anthropic`    Messages API with `stream = true`.
`codex`        ChatGPT plan through the Codex CLI. No API key.
`claude_code`  Claude plan through Claude Code. No API key.
`copilot`      GitHub Copilot plan through an existing Copilot sign-in.
`mock`         Offline. Streams `response` (edits) or `answer` (ask), each
               a string or a function of the request, in chunks. Used by
               the tests and the demo.

Each entry accepts `base_url`, `model`, `api_key_env`, and `api_key`. An
entry with `format = "openai"` or `format = "anthropic"` reuses that wire
format under its own name: >lua
    providers = {
      ollama = { format = "openai", base_url = "http://localhost:11434/v1",
                 model = "qwen2.5-coder", api_key = "ollama" },
    }
<
                                                         *quill-subscriptions*
Subscription providers ~

`codex` and `claude_code` run the CLI once per request. The prompt goes on
stdin and quill reads the CLI's JSON event stream. Setup: >sh
    npm i -g @openai/codex && codex login
    npm i -g @anthropic-ai/claude-code   # then run `claude` and `/login`
<
Options for both:
    `cmd`         Executable. Defaults to `codex` or `claude` on $PATH.
    `args`        Replaces the default flags below.
    `model`       Passed as `-m` (codex) or `--model` (claude). Unset uses
                  the CLI's default.
    `timeout_ms`  Kill the CLI after this long. Default 120000.
    `cwd`         Working directory. Default |stdpath()| "cache".

Default `args` for `codex`, followed by `-` so the prompt is read from
stdin: >
    exec --json --sandbox read-only --skip-git-repo-check --ephemeral
    --color never
<
Default `args` for `claude_code`, followed by `--system-prompt`: >
    -p --output-format stream-json --verbose --include-partial-messages
    --tools "" --strict-mcp-config --no-session-persistence
<
Claude Code streams text as it arrives. Codex reports its answer whole when
the turn ends, so the preview appears at once.

`copilot` reads the OAuth token that copilot.vim or copilot.lua saved in
`$XDG_CONFIG_HOME/github-copilot/apps.json` or `hosts.json` (default
`~/.config`), exchanges it at `token_url` for a short-lived API token, caches
that until a minute before it expires, and streams Chat Completions from the
endpoint the exchange returns. Sign in once with `:Copilot setup`
(copilot.vim) or `:Copilot auth` (copilot.lua). Options: `model` (default
"gpt-5-mini"), `config_dir`, `token_url`, `base_url` (used when the exchange
returns no endpoint).

The Copilot token exchange is GitHub's internal, undocumented API. It is not
a public interface and may change or stop working without notice.

7. HIGHLIGHTS                                               *quill-highlights*

Diff colors are mixed from the colorscheme's |hl-DiagnosticError| and
|hl-DiagnosticOk| colors over |hl-Normal| and recomputed on |ColorScheme|.
All groups are defined with `default = true`, so a colorscheme or your config
can override them. Without 'termguicolors' the diff groups link to
|hl-DiffDelete|, |hl-DiffAdd|, and |hl-DiffText|.

  QuillDelete         Removed lines of the current hunk.
  QuillDeleteText     Changed words inside a removed line.
  QuillDeleteDim      Removed lines of other hunks.
  QuillDeleteAccepted Removed lines of an accepted hunk.
  QuillAdd            Added lines of the current or an accepted hunk.
  QuillAddText        Changed words inside an added line.
  QuillAddDim         Added lines of other hunks.
  QuillFlash          Brief highlight after accepting or applying.
  QuillPending        Lines the model has not reached yet while streaming.
  QuillSignDelete  QuillSignAdd  QuillSignDim  QuillSignAccepted
                      Sign column marks.
  QuillKey  QuillKeyLabel  QuillInlineKey  QuillInlineLabel  QuillCounter
                      Key chips in the status float and on the current hunk.
  QuillStatus  QuillMuted  QuillSpinner  QuillDone  QuillPlus  QuillMinus
                      Status float text.
  QuillFloat  QuillBorder  QuillTitle  QuillPlaceholder  QuillPromptIcon
  QuillGutter         Floats, the prompt, and the virtual-line gutter.
  QuillAskKey  QuillAskLabel
                      Footer keys in the ask box. The key color is the
                      quill accent (#E5482D).
  QuillAskRef  QuillAskBuf
                      Referenced code in the ask box and the matching
                      ranges in the source buffer.
